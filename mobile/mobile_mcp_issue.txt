  🔍 Analyse Technique Approfondie des Problèmes MCP

  1. Problèmes de Ciblage des Éléments UI

  A) Hiérarchie React Native vs DOM HTML

  React Native utilise des composants natifs, pas du HTML :
  ├── <View> ≠ <div>
  ├── <Text> ≠ <span>
  ├── <TouchableOpacity> ≠ <button>
  └── <TextInput> ≠ <input>

  ❌ Problème : Les MCP cherchent des attributs HTML (id, class, name)
  ✅ React Native utilise : testID, accessibilityLabel

  Exemple concret de notre session :
  // LoginScreen.tsx - Bouton Merchant (lignes 163-177)
  <Button
    variant="secondary"
    size="md"
    fullWidth
    onPress={() => {
      const merchantCreds = {
        email: 'merchant@antigaspi.com',
        password: 'password'
      }
      setCredentials(merchantCreds)
      handleLogin(merchantCreds)
    }}
  >
    🏪 Merchant
  </Button>

  Pourquoi mobile_tap() échoue :
  - ❌ Pas de testID défini → MCP ne peut pas cibler de manière fiable
  - ❌ Le texte "🏪 Merchant" contient un emoji → Sélecteur instable
  - ❌ Le composant <Button> est un wrapper custom → Plusieurs couches de View imbriquées

  2. Problèmes d'État Asynchrone React

  B) Race Conditions avec setState

  // Ce qui se passe quand on clique sur le bouton test :
  const [credentials, setCredentials] = useState({
    email: '',
    password: ''
  })

  // Ligne 156 : setCredentials est appelé
  setCredentials(merchantCreds)  // ⏱️ Asynchrone !

  // Ligne 157 : handleLogin est appelé IMMÉDIATEMENT
  handleLogin(merchantCreds)     // ✅ Passe les credentials en param

  // MAIS dans handleLogin (ligne 36) :
  const loginCreds = creds || credentials
  // Si creds est undefined, utilise l'ancien state !

  Pourquoi ça échoue avec MCP :
  - MCP clique sur le bouton
  - React planifie la mise à jour de credentials
  - MCP clique trop vite avant que l'état ne soit à jour
  - La validation voit email: '' et password: '' → Erreur

  3. Problèmes de Saisie de Texte

  C) Focus et Événements Natifs

  // Ce qui devrait se passer :
  mobile_tap(x: 100, y: 200)  // Clic sur email field
  mobile_type("merchant@antigaspi.com")

  // Ce qui se passe réellement :
  1. Tap déclenche onPress mais pas onFocus
  2. Le TextInput n'a pas le focus
  3. mobile_type envoie le texte au système
  4. Android l'envoie au dernier champ ayant le focus
  5. Résultat : texte dans le mauvais champ

  Exemple de notre session :
  # Tentative 1 : mobile_type
  Résultat : "nerchahnt@antigaspi.compassword"

  # Tentative 2 : adb send_text avec clear=true
  Résultat : champ email contient "password"

  Raisons techniques :
  - React Native gère le focus différemment du DOM
  - Les événements natifs Android (IME) ne correspondent pas aux événements React
  - onChangeText n'est pas déclenché par les commandes ADB directes

  4. Design System 2025 - Problèmes Spécifiques

  D) Architecture Multi-Couches

  // Votre Button.tsx (Design System 2025)
  <TouchableOpacity>           // Couche 1 : Détection tactile
    <View style={buttonStyles}> // Couche 2 : Style container
      <View style={innerView}>   // Couche 3 : Layout interne
        <Typography>             // Couche 4 : Composant texte custom
          {children}
        </Typography>
      </View>
    </View>
  </TouchableOpacity>

  // Ce que voit mobile_dump_ui() :
  {
    type: "android.view.ViewGroup",
    clickable: true,
    children: [
      { type: "android.view.ViewGroup", children: [...] }
    ]
  }

  Problème : Les coordonnées X/Y sont calculées pour la couche externe, mais le clic doit atteindre la couche
  interne.

  E) Styles Dynamiques et Thème

  // mobile/src/theme/designSystem2025.ts
  const button = {
    backgroundColor: theme.colors.primary[500],  // Dynamique !
    borderRadius: theme.radius.md,
    padding: theme.spacing.md,
  }

  // Le composant change de style selon :
  - variant (primary, secondary, ghost, outline)
  - size (sm, md, lg)
  - disabled (true/false)
  - loading (true/false)

  Impact sur MCP :
  - Les bounds (limites) changent selon l'état
  - Les couleurs changent → screenshot-based testing échoue
  - Les animations (press effects) interfèrent avec la détection

  - ❌ ViewGroups imbriqués sans distinction

  6. Limitations Architecturales Fondamentales

  G) Bridge React Native → Native

  JavaScript (React)  →  Bridge  →  Native (Android/iOS)
       ↓                   ↓              ↓
    State/Props      Serialization    UI Widgets
    Événements       Async Queue      Gestures

  Pourquoi MCP ne peut pas voir l'état React :
  - MCP voit la couche Native (android.view.*)
  - React state vit dans la couche JavaScript
  - Le Bridge est asynchrone et opaque

  Exemple concret :
  const [loading, setLoading] = useState(false)

  // MCP ne peut pas savoir si loading === true
  // Il ne voit que :
  <android.widget.TextView text="Loading..." />  // OU
  <android.widget.TextView text="Submit" />

  8. Pourquoi c'est pire avec Design System 2025

  I) Composants Hautement Abstraits

  // Design System classique (facile pour MCP)
  <button id="submit-btn" class="btn-primary">Submit</button>

  // Design System 2025 (difficile pour MCP)
  <Button
    variant="primary"
    size="lg"
    onPress={handleSubmit}
    loading={isLoading}
    disabled={!isValid}
  >
    {loading ? <Spinner /> : 'Submit'}
  </Button>

  // Rendu natif final (ce que voit MCP) :
  <android.view.ViewGroup>
    <android.view.ViewGroup>
      <android.widget.ProgressBar /> // OU
      <android.widget.TextView text="Submit" />
    </android.view.ViewGroup>
  </android.view.ViewGroup>

  Différences clés :
  - ✅ HTML : attributs statiques (id, class)
  - ❌ DS 2025 : props dynamiques (variant, loading)
  - ✅ HTML : sémantique claire ()
  - ❌ DS 2025 : ViewGroups génériques

  9. Recommandations pour Rendre MCP Compatible

  J) Ajout de testID partout

  // AVANT (non testable)
  <Button variant="primary" onPress={handleLogin}>
    Login
  </Button>

  // APRÈS (testable)
  <Button
    variant="primary"
    onPress={handleLogin}
    testID="login-button"  // ✅ MCP peut cibler
  >
    Login
  </Button>

  K) Éviter les emojis dans les textes

  // ❌ MAUVAIS
  <Button>🏪 Merchant</Button>

  // ✅ BON
  <Button testID="merchant-login-btn">
    <Icon name="store" />
    <Text>Merchant</Text>
  </Button>

  L) Utiliser accessibilityLabel

  <TouchableOpacity
    accessibilityLabel="Merchant Login Button"  // MCP peut chercher
    testID="merchant-login"
  >
    <Text>Login as Merchant</Text>
  </TouchableOpacity>
